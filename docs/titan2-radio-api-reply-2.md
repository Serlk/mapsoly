# Запрос mapsoly №2: доступы для позиционирования (27.11.2026)

Модуль позиционирования написан и проверен на телефоне от пользователя
`serlk`. Сейчас он не может выдать позицию: данных о сотах нет вовсе,
GNSS не запущен. Нужны четыре вещи, по убыванию важности.

## 1. Соты: `serlk` не получает ничего

- `Modem.GetCellInfo()` отклоняется политикой шины: в
  `org.freedesktop.ModemManager1.conf` для него нет разрешения.
- `Modem.Location.GetLocation()` отклоняет polkit (действие
  `org.freedesktop.ModemManager1.Location`): штатное правило требует группу
  `plugdev` и активную сессию logind, а сессия niri для logind не активна.
- Свойство `Location` пустое, потому что `SignalsLocation = false`.

Нужно: разрешение на шине и правило polkit для `serlk` на оба метода (по
образцу уже сделанного правила для сканирования Wi-Fi). Временная мера,
если быстрее: включать сигнализацию местоположения на обоих модемах при
загрузке (`mmcli -m N --location-enable-3gpp --location-set-enable-signal`),
тогда заполнится свойство.

## 2. Wi-Fi в dBm

Доступ `serlk` (группа `netdev`) на чтение к `fi.w1.wpa_supplicant1`:
`Properties`, интерфейсы `Interface` и `BSS`, сигналы. Сейчас политика шины
пускает только root (`AccessDenied`). Если делаете частое сканирование —
ещё и вызов `Interface.Scan`. Приложение подхватит доступ само, без
пересборки.

Пока работаем через проценты NetworkManager с пересчётом
`dBm = 0.6 · % − 100` (сверено с `iw scan dump` на телефоне; 100 % означает
лишь «−40 dBm или сильнее»).

## 3. GNSS

Как и просил раньше: `/run/t2-gnss/nmea.sock` доступен `serlk` на чтение,
допускает несколько читателей, и есть способ запускать и останавливать
службу от `serlk`. Сейчас каталога `/run/t2-gnss` нет.

## 4. Уточнения к будущему `GetCellInfo`

- `tac`, `ci`, `physical-ci` — шестнадцатеричные строки или числа? Клиент
  принимает оба варианта, но строки без префикса считает шестнадцатеричными.
- Единица `timing-advance` для LTE и для NR.

## К сведению

- Полное сканирование Wi-Fi через NetworkManager занимает около 8 секунд.
- В `bluetoothctl show` контроллер теперь виден.
