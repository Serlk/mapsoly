# Ответ mapsoly на ANSWER-20261127 (Wi-Fi, GNSS)

## Wi-Fi

1. **dBm нужен.** `Strength` в процентах — уже сжатая и обрезанная величина,
   расстояние по ней считать плохо. Нужен доступ `serlk` к D-Bus
   wpa_supplicant (`fi.w1.wpa_supplicant1`): свойства BSS `BSSID`,
   `Frequency`, `Signal` (dBm), `Age`, сигналы `BSSAdded` / `PropertiesChanged`
   / `ScanDone`. Если у wpa_supplicant это закрыто политикой D-Bus — открыть
   на чтение для группы `netdev`.
2. **Свежесть 10–15 с** годится для стоянки и пешехода, но в машине это
   150–250 м между обновлениями. Цель для режима «навигация без GPS» —
   новый скан раз в 3–5 с. Прошу проверить два способа:
   - прямой `Interface.Scan` в wpa_supplicant в обход ограничения
     NetworkManager;
   - скан по сокращённому списку каналов (`Channels` в аргументах `Scan`):
     1, 6, 11 и те каналы 5 ГГц, где реально были точки в прошлом полном
     скане. Он в разы короче полного и меньше мешает передаче данных.
   Частый скан нужен только пока приложение его просит; в остальное время —
   как сейчас.
3. `LastSeen` в секундах CLOCK_BOOTTIME — принято, устаревшие точки
   отбрасываю по нему.

## GNSS

Приложение будет читать NMEA напрямую из `/run/t2-gnss/nmea.sock`: через
GeoClue теряются GSV/GSA, а они нужны для оценки качества и обнаружения
подмены. Прошу:

- группу/права на сокет для `serlk`;
- способ запускать и останавливать службу `t2-gnss` от `serlk` (или запуск
  по подключению к сокету), чтобы GNSS не работал, когда карта закрыта;
- сокет должен допускать несколько читателей одновременно (приложение и
  GeoClue).

Сырые измерения по спутникам не обязательны.

## Соты и Bluetooth

Сроки приняты. Порядок важности для приложения: соты → Wi-Fi dBm и частый
скан → BLE-сканирование → RFCOMM для ELM327 → GATT.
